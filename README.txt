OPEN THE APPLICATION

Requires a 64-bit Python 3.11, 3.12 or 3.13 environment.

1. Extract the ZIP and open the quant_risk_exercises folder in your editor.
2. Select a virtual or Conda environment for this project and open its terminal.
3. Copy and run these two commands from the project folder:

       python -m pip install -r requirements.txt
       python -m streamlit run app.py --server.showEmailPrompt false --theme.base light

The first command installs the required packages in the selected environment.
Use an environment dedicated to this project, as the package versions are
pinned. This setup needs an internet connection and may take a few minutes.
The second command opens the app in its light theme without the email prompt.
If a browser tab does not open, click the Local URL printed in the terminal.

On later visits, only run the second command. Keep the terminal open while
using the app; Ctrl+C stops it. These commands work from an activated Python
environment on Windows, macOS or Linux.

WHAT TO EXPLORE

The opening page puts the gas storage tool alongside the main option results.
It connects each day's price and trading decision to the storage fill and the
inventory path over the year. Playback starts at four days per second. Starred
controls select the saved finer-grid and Sobol + bridge experiments.

The sidebar opens the four exercises. Their tables and charts use saved results;
exploring them does not rerun the numerical studies.

TEST DATA AND REPRODUCIBILITY

test_data/ is the test-data deliverable. Each exercise has a readable cases.json
with inputs, expected answers, sources, units and tolerances. The existing tests
read these files directly. Published tables and example paths are supplied as
CSVs; the gas-storage CSV exposes one complete saved operating path.

    exercise1/   Longstaff-Schwartz Table 1 and eight-path example; Euler and
                 exercise-decision checks.
    exercise2/   European control, Barone-Adesi-Whaley Table IV and gamma checks.
    exercise3/   Euler/Milstein comparisons, cross-integral law and boundary cases.
    exercise4/   Final-day trades, analytical short contracts, constant-price
                 storage and the saved operating replay.

Run python -m pytest -q for 42 automated tests covering numerical calculations,
reproducibility, error handling, saved-file integrity and all five application
pages. A successful run reports 42 passed.

The numerical checks include the eight-path worked example in Section 1 of
Longstaff-Schwartz (2001), and five positive-rate American-put prices from
Barone-Adesi-Whaley (1987), Table IV. Other checks use analytical formulas,
prescribed cases and the assignment's operating constraints. The saved
gas-storage replay checks consistency with the recorded path and decisions.

The full Longstaff-Schwartz Table 1 comparison is a separate numerical study;
it is not rerun by this test command. test_data/README.txt explains each file,
reference and tolerance.

The valuation studies generate their price paths from the specified models.
Training paths estimate continuation values and decision rules; independently
generated evaluation paths measure the resulting value. The runners record the
model and contract inputs, path counts and random seeds in their result files.
The supplied results also record the numerical-library versions used.

results/ contains the saved numerical outputs used by the report and UI.
The gas-storage NPZ includes fitted coefficients, training and evaluation
cashflows, and selected operating paths for replay. It does not archive every
simulated price path: those are generated by the supplied code from the recorded
inputs and seeds. No historical-market-data download is required.

IF THE APPLICATION DOES NOT OPEN

- If Python is not found, open a terminal for the environment selected in your
  editor. Python must be available in that environment.
- If package installation is blocked, install requirements.txt through your
  organisation's approved package route, then run the second command above.
- If port 8501 is already in use, add --server.port 8502 to the launch command.
- Keep the extracted folder together. Virtual environments must be created on
  the computer where they run; recreate one if it was copied from elsewhere.

CODE STRUCTURE

The shared modules describe market inputs, products, models, simulation,
regression bases, controls and valuation. Each exercise adds its own methods
and result views without duplicating that core.

exercise1/   American option valuation and published-price comparisons.
exercise2/   European control variate, Barone-Adesi-Whaley reference and gamma.
exercise3/   Euler and Milstein, including the double stochastic integrals.
exercise4/   Gas price paths, storage decisions, independent integration
             benchmark and the finer-grid/Sobol extensions.
app.py       Navigation and project overview.
assets/      Interactive gas storage replay.
results/     Saved numerical studies and their integrity checks.
reports/     Complete written assignment.
test_data/   Test inputs, expected answers, sources and acceptance tolerances.
tests/       Numerical identities, operating constraints and UI checks.

CHECKS AND NUMERICAL STUDIES

From the same project environment and folder:
    python -m pytest -q
    python -m exercise4.storage_extensions --check

The exercise runners are separate from the application. For example:
    python -m exercise4.run_exercise4 --help
    python -m exercise4.run_exercise4 --study main --workers 4

The other entry points are exercise1.run_exercise1, exercise2.run_exercise2,
exercise3.run_exercise3, exercise4.gas_storage_benchmark and
exercise4.storage_extensions. Each accepts --help.

New runs default to timestamped folders under runs/. The application continues
to display results/. Keep each Exercise 4 JSON and its companion NPZ together.
